# 敌人系统开发记录

> 最后更新：2026-08-19  
> 状态：最小敌人地基、场景生成、四方向表现、战斗反应与 Actor 版连续怪潮堆积闭环已落地

## 文档用途

本文档持续记录敌人系统的协议、运行时实现、关卡接入方式、PIE 验收方法和后续演进方向。

代码与已保存的资产是事实来源；本文档用于解释当前边界和记录后续决策。

## 当前设计边界

敌人上层逻辑只依赖句柄、请求、状态和事件，不直接依赖 Actor。当前以 Actor 作为最小运行时后端，后续可增加 Mass Entity 后端而不修改战斗协议。

- `FCombatantHandle`：跨系统引用敌人的稳定句柄。
- `FCombatDamageRequest` / `FCombatDamageResult`：伤害输入和结果协议。
- `FEnemySpawnRequest` / `FEnemySpawnResultData`：单个敌人的生成命令和异步结果。
- `FCombatantSnapshot`：目标查询使用的后端中立队伍、位置、逻辑胶囊与存活快照。
- `FEnemyTargetData` / `FEnemyMoveIntent` / `FEnemyMovementData`：不含 Actor、Controller 或路径对象的目标和移动协议。
- `FGobulinEnemyCrowdDefinition` / `FGobulinEnemyCrowdData`：不含 Actor 的怪潮规则与局部压力观测数据，后续可映射为 Mass Fragment。
- `EEnemyState`：敌人生命周期状态。
- `UCombatEventSubsystem`：C++ 事件总线。
- `UGobulinEnemySubsystem`：World 级敌人生命周期服务，负责定义加载、实例创建、状态推进和回收。
- `AGobulinEnemyActor`：基于 `ACharacter` 的当前 Actor 后端，承载碰撞、地面移动和表现，不作为关卡直接摆放对象。
- `AGobulinEnemyAIController`：只执行 NavMesh 路径请求，不拥有索敌、状态机或攻击决策。
- `UGobulinEnemyPresentationComponent`：基于原生 `UPaperFlipbookComponent` 的 Actor 表现适配器。
- `AGobulinEnemySpawnArea`：可放入关卡的区域生成入口，负责寻找地面锚点并提交批量请求。
- `AGobulinEnemySwarmBoundary`：只阻挡活敌和尸体的关卡硬边界；不用于标记哪些普通物体可以攀爬。
- `UGobulinEnemyArchetype`：Actor 与未来 Mass 后端共用的数据定义。
- `AGobulinEnemyPreviewActor`：仅编辑器存在的装配台，用于在关卡视口调整身体与纸片表现并烘焙回 Archetype。

当前最小状态流为：

`Inactive -> Spawning -> SeekingTarget -> Moving <-> ReadyToAttack -> Dying -> Inactive`

任意存活行为状态受到伤害时，可进入 `HitReacting`（普通短打断）或 `Staggered`（重击/阈值硬直），结束后回到 `SeekingTarget`。致死伤害直接进入 `Dying`，不再经过普通受击恢复。

基本敌人的 `ReadyToAttack` 表示已经与当前目标建立有效胶囊接触；接触期间按配置节拍提交伤害，脱离后返回 `Moving`。目标失效或超出保持距离时，`Moving / ReadyToAttack` 会返回 `SeekingTarget`。`AttackWindup / AttackActive / AttackRecovery` 仍保留给后续非接触型敌人，本基本单位不使用。

## 默认敌人定义

- 资产：`/Game/_Game/Enemy/EA_BasicEnemy`
- Primary Asset ID：`EnemyArchetype:EA_BasicEnemy`
- 资源扫描目录：`/Game/_Game/Enemy`
- 身体：胶囊半径 `34 cm`、半高 `88 cm`
- 默认移动表现：`FieldPaladin__Idle_D/U/L/R` 与 `FieldPaladin__Run_D/U/L/R`
- 当前临时死亡表现：`BattlePaladin__Downed`（FieldPaladin 尚未提供死亡 Flipbook）
- 移动速度：`300 cm/s`
- 搜索/丢失目标距离：`5000 / 6500 cm`
- 接触伤害：每次 `10`，独立间隔 `0.8 s`，进入/脱离胶囊表面容差 `5 / 15 cm`
- 行为决策间隔：`0.25 s`；导航失败重试：`1.0 s`
- 连续堆积默认开启；开启后关闭 RVO，活敌之间改用局部空间网格和虚拟拥挤粒子求解
- 普通受击打断：`0.12 s`；单次实际伤害达到最大生命 `30%` 或攻击标签为 `Combat.Attack.Melee.Heavy` 时进入 `0.45 s` 硬直
- 剑命中速度：水平 `220 cm/s`、垂直 `90 cm/s`；致死水平倍率 `2.2`、最小垂直速度 `420 cm/s`
- 死亡动画默认循环；死亡总时限 `4.0 s`，落地停留 `0.35 s` 后用 `0.45 s` 淡出

## 索敌与移动

索敌和移动决策归 `UGobulinEnemySubsystem`，而不是 AIController、Behavior Tree 或每个敌人的 Actor Tick。

### 战斗单位快照

`UCombatantRegistrySubsystem` 除了维护句柄到 Actor 后端的映射，还提供 `FCombatantSnapshot`：

- `Handle`：稳定战斗句柄；
- `TeamId`：用于排除同队目标；
- `Location`：本次决策读取的位置快照；
- `BodyShape`：不引用组件的直立胶囊半径与半高；
- `bActive`：死亡或不可再成为目标时为 false。

玩家默认注册为队伍 `1`，SpawnArea 默认生成队伍 `0`。敌人只在搜索半径内选择最近的存活异队单位；距离完全相同时按句柄排序，保证结果稳定。当前不检查视野锥和视线遮挡。

### 决策与路径执行

- EnemySubsystem 按 Archetype 的 `DecisionInterval` 分批更新敌人，并按句柄错开更新时间。
- `FEnemyMoveIntent` 只包含目标句柄、目的地快照、速度、停止距离、时间和递增序号。
- Actor 后端把意图交给轻量 `AGobulinEnemyAIController`，由 NavMesh 和 `UCharacterMovementComponent` 跟随移动目标。
- Controller 不使用 Behavior Tree、Blackboard 或 AI Perception；路径完成后只把 `Reached / Blocked / Failed` 结果回报 EnemySubsystem。
- MoveTo 的中心停止距离由双方胶囊半径与接触进入容差动态计算，不再使用固定的宽距离攻击区。
- `ReadyToAttack` 使用胶囊表面 `ContactEnterTolerance / ContactExitTolerance` 形成滞回；MoveTo 报告 `Reached` 不代表接触成立，仍须通过逻辑胶囊和遮挡验证。
- 连续堆积关闭时，路径失败会清理当前目标并等待 `NavigationRetryDelay`；连续堆积开启时则保留目标并进入瞬态 `CrowdPushing`，先用 CharacterMovement 输入继续向目标施压。NavMesh 返回的“完整路径”只是一条候选路径：`Moving` 落地期间若实际水平速度低于阈值、持续没有缩短到目标的三维距离，或者 PathFollowing 明确回报 `Blocked`，EnemySubsystem 会否决当前路径并记录拒绝时的敌人/目标上下文。
- 被否决的路径不能仅凭重试计时结束再次恢复。只有敌人中心高度变化、目标移动，或敌人与目标的距离改善达到配置阈值，才允许重新做只读完整路径探测；探测成立后才重新提交 MoveTo。普通 `CrowdPushing` 仍按 `FallbackNavigationRetryInterval` 与句柄稳定错峰探测；探测失败不会清空当前速度，Falling 期间暂停探测，落地后再恢复。
- 连续堆积开启时关闭 CharacterMovement RVO，避免两套近邻分离规则互相拉扯；关闭连续堆积的特殊敌人仍可使用 Archetype 中的 RVO 配置。

### 连续怪潮堆积（Actor 第一轮）

当前实现不是在敌人头顶分配固定站位，也没有“攀爬者/支撑者”关系。EnemySubsystem 每帧为存活敌人建立三维局部空间网格，只检查相邻网格内的虚拟拥挤粒子：

- 虚拟粒子半径由逻辑胶囊半径乘 `ParticleRadiusScale` 得到，默认小于战斗胶囊，因此纸片可以形成有遮叠的紧密怪潮。
- `NeighborRangeScale` 只决定局部密度统计范围；达到 `MinimumLiftNeighborCount` 后，后排且朝目标推进的敌人才会把重叠压力转换成向上速度。
- 朝目标的回退推进与水平分离通过 `AddMovementInput` 交给 `UCharacterMovementComponent`，使其产生可持续加速度，不再使用会被地面制动立刻吃掉的逐帧水平冲量；只有垂直抬升继续使用受最大速度限制的冲量。重力、落地和普通世界碰撞仍由 CharacterMovement 处理，不直接改 Actor Transform，也不启用 Chaos 刚体堆叠。
- 敌人仍会被 `WorldStatic / WorldDynamic` 阻挡，但局部压力足够时可以先沿前排上升，再越过普通矮墙、门体或防御设施。系统不读取 `Pileable` 白名单。
- `AGobulinEnemyActor` 使用专用 `UGobulinEnemyMovementComponent`，基础敌人始终允许走下边缘。普通胶囊地面扫描即使仍命中锐利墙沿，组件也会额外用 `GroundSupportRadius` 对脚底中心做小胶囊扫描；中心失去支撑，或下方地面超过 `GroundSnapDownHeight`，就在同一次移动更新中进入 Falling。该过程不等待停滞计时、不切换到 `CrowdPushing`、不沿边寻找左右替代方向，也不预先要求安全落点。
- `MaximumPileHeight` 是相对出生中心高度的异常保护，不是关卡可见的固定层数。需要禁止到达的区域，应使用空气墙或 `AGobulinEnemySwarmBoundary`。
- 第一轮仍由 Actor 根胶囊同时承担世界移动、玩家阻挡和战斗命中；敌人之间则忽略根胶囊刚体碰撞。第二轮会把战斗身体与拥挤粒子彻底拆分，并把网格、压力与速度数据映射为 Mass Fragment/Processor。

主要调参入口位于 `UGobulinEnemyArchetype.Crowd`：

- `ParticleRadiusScale`：怪潮横向紧密程度；越小越容易互相遮叠。
- `NeighborRangeScale / MinimumLiftNeighborCount`：形成向上压力所需的局部密度。
- `HorizontalSeparationAcceleration`：防止敌人完全穿过彼此的水平修正。
- `UpwardPressureAcceleration / MaximumLiftSpeed`：爬升速度和喷射感。
- `FallbackDriveAcceleration`：导航失败后继续朝目标推挤的力度。
- `FallbackNavigationRetryInterval`：停留在 `CrowdPushing` 时探测 NavMesh 完整路径的基础间隔；默认 `0.5 s`，每个句柄实际使用 `75%-125%` 的稳定错峰间隔。
- `NavigationStallTimeout / NavigationMinimumTargetProgress / NavigationStallSpeedThreshold`：导航执行看门狗；默认在落地 `Moving` 敌人水平速度低于 `10 cm/s`、`1.5 s` 内未累计缩短至少 `5 cm` 目标距离时否决路径。
- `NavigationRecoveryDistance / NavigationRecoveryHeight`：被否决后允许重新尝试导航的上下文变化阈值；默认目标移动或目标距离改善 `75 cm`，或者敌人中心高度变化 `45 cm`。单纯等待不会满足恢复条件。
- `GroundSupportRadius`：脚底中心有效支撑半径，默认 `3 cm`。推荐保持在 `2-4 cm`；过大会重新允许明显悬边，过小会放大地面三角形接缝。
- `GroundSnapDownHeight`：仍按连续地面吸附的最大向下距离，默认 `8 cm`。更大的台阶或落差直接进入 Falling。
- `MaximumPileHeight`：技术性高度保护。

### 接触伤害

- 不创建额外 Overlap 触发器，也不依赖持续接触时不稳定的 `OnHit`。EnemySubsystem 在已有低频行为更新中判断双方直立胶囊轴线距离。
- 几何距离成立后，以 `CombatTrace` 从敌人中心查询到目标中心；世界阻挡位于两者之间时不建立接触，因此不会隔薄墙扣血。
- 首次有效接触立即提交一次 `FCombatDamageRequest`，之后每个敌人按自己的 `DamageInterval` 重复提交。
- 每个敌人一次只伤害当前目标；脱离不会清空 `NextDamageTime`，快速进出不能绕过冷却。
- 卡顿后只提交当前一次，不追赶和补发历史伤害节拍。敌人或目标死亡后会清理接触。
- 默认攻击/伤害标签为 `Combat.Attack.Melee` 与 `Combat.Damage.Physical`；最终扣血仍由 CombatSubsystem 和目标端点完成。
- 当前没有玩家侧全局接触无敌时间；多个敌人的有效接触伤害会独立叠加，待多敌人 PIE 手感验证后再决定是否加入目标侧伤害预算。

### 受击、硬直与致死击飞

- `FCombatDamageRequest.Impulse` 是伤害源提供的后端中立位移建议。当前剑按“攻击者到目标”的水平向量写入轻微击退和垂直速度；敌人 Actor 后端用 `LaunchCharacter` 执行，不直接修改 Actor Transform。
- 每次实际剑伤都会停止当前 MoveTo、离开接触伤害状态并进入 `HitReacting`。普通反应至少持续 `LightInterruptDuration`，若仍在空中则等待落地；`MaximumAirborneReactionDuration` 是异常地形保护上限。
- 普通击飞和硬直期间暂停四方向速度判定，固定播放 `TowardViewer Idle`，也就是面向本地玩家的序列帧；落地并结束反应后才恢复按实际速度切换方向。致死阶段仍使用独立的 `Death` Flipbook。
- 单次实际伤害比例达到 `StaggerDamageRatioThreshold`，或攻击标签匹配 `HeavyAttackTag` 时进入 `Staggered`。硬直结束后有独立免疫窗，连续高频命中仍会闪白和击退，但不能永久锁住状态。
- 致死伤害立即让战斗注册快照失活、切换 Death Flipbook、闪红并进入真实击飞。水平速度按 Archetype 倍率放大，垂直速度有最小保证，最终速度受 `MaximumLaunchVelocity` 限制，避免外部物理冲量把角色发射出关卡。
- 死亡期间逐渐变黑；尸体首次落地后停止 CharacterMovement，保持一段时间再把不透明度降到 0。当前退役点仍销毁 Actor，但已经集中在 EnemySubsystem，后续对象池可在此替换为回收。
- 普通白闪、致死红闪、逐黑和淡出只通过 PaperFlipbookComponent 的 Custom Primitive Data 更新，不为每个敌人创建 MID。约定索引为：`0` 闪色时间包络、`1` 普通/致死选择器、`2-3` 保留、`4` 逐黑强度、`5` 不透明度。颜色和峰值覆盖强度来自共享材质或材质实例参数。

### 事件边界

- `FEnemyTargetChangedEvent`：只在获得、失效、超距或导航失败导致目标变化时发布。
- `FEnemyMoveStatusChangedEvent`：发布 `Moving / CrowdPushing / Reached / Blocked / Failed` 等语义变化。
- 目标位置和路径跟随的逐帧更新不进入事件总线。

未来 Mass 后端应将 `FCombatantSnapshot.BodyShape` 接到空间查询，把 RuntimeStats 放入 Const Shared Fragment，把 Target/Movement/ContactDamage 放入每实体 Fragment；不为普通杂兵创建 ACharacter、AIController 或接触触发组件。

## 战斗命中通道

近战形状查询统一使用项目专用 Trace Channel：`CombatTrace`（C++ 为 `ECC_GameTraceChannel2`），不再复用 `Visibility`。

- 默认响应为 `Block`，因此场景遮挡仍能截断一次武器查询。
- 敌人胶囊对 `CombatTrace` 显式设为 `Overlap`，`SweepMultiByChannel` 可以在命中多个敌人后继续查询。
- 存活敌人胶囊使用 `EnemyBody`（`ECC_GameTraceChannel4`）Object Type：阻挡玩家和世界、响应 `CombatTrace`，但活敌之间互相 Ignore，由连续怪潮求解器负责空间分离。生成空间检查仍以胶囊对 `Pawn` 查询通道的 Block 响应判断占位。
- 进入 `Dying` 后胶囊切换为 `EnemyCorpse`（`ECC_GameTraceChannel3`）。该物体通道的项目默认响应必须是 `Block`，确保地面和现有场景组件也愿意阻挡尸体；尸体胶囊自身再显式只阻挡 `WorldStatic`、`WorldDynamic` 和其他 `EnemyCorpse`，忽略 `Pawn`、`CombatTrace` 与其他通道。这样玩家和存活敌人不会被尸体卡住，尸体之间仍保留空间，也不会穿过地面。
- 尸体不可被角色踩作移动基底；活敌堆积使用独立的虚拟拥挤粒子，不复用尸体通道。
- `EnemySwarmBoundary`（`ECC_GameTraceChannel5`）默认被其他对象忽略，只与 `EnemyBody / EnemyCorpse` 双向 Block。普通墙体不要改成该通道，否则会失去“数量形成自然越障”的玩法。
- 接触伤害在胶囊距离成立后使用该通道确认目标与敌人之间没有世界阻挡；其他敌人的 Overlap 响应不会截断这条查询。
- 查询命中依赖 Collision Response，不依赖 `Generate Overlap Events`；敌人无需开启逐帧重叠事件。
- 修改通道配置或首次启用 Paper2D 后必须重启编辑器，已有 PIE 会话不会热重载碰撞通道定义。

## Paper2D 表现层

当前 Actor 后端不再读取自研图集行列并由程序切帧，而是直接消费虚幻原生 `UPaperFlipbook`。Flipbook 的帧、帧率、关键帧 Sprite 和默认材质均可在 Paper2D 编辑器中调整。

运行时组件层级固定为：

`CollisionCapsule -> FeetAnchor -> Presentation (PaperFlipbook)`

- Actor 世界原点仍是胶囊中心。
- `FeetAnchor` 始终位于胶囊底部。
- `VisualTransformFromGround` 保存纸片相对脚底的位移、旋转和缩放，胶囊尺寸变化不会破坏脚底对齐。
- 基本敌人包含四方向 `Idle`、四方向 `Run` 与一个 `Death`，合计九个表现槽。
- 每套方向槽分别表示朝向观察者、远离观察者、向观察者屏幕左侧和右侧移动；不是世界东南西北，也不读取目标方向。
- FieldPaladin 资源映射为：`D -> TowardViewer`、`U -> AwayFromViewer`、`L -> ViewerLeft`、`R -> ViewerRight`。
- 运行时使用敌人的实际水平速度相对本地相机选方向，因此 NavMesh 转弯和 RVO 避让也能得到正确表现。
- 速度达到 `MinimumDirectionalSpeed` 时循环播放该方向 `Run`；低于阈值时循环播放上一次有效方向的 `Idle`。
- `DirectionSwitchHysteresis` 在四方向分界附近提供切换滞后；同一动作内切换方向时继承标准化播放进度，`Idle <-> Run` 切换则从头播放。
- `Death` 是否循环由 Archetype 的 `bLoopDeathFlipbook` 配置，`EA_BasicEnemy` 当前开启循环。普通受击、硬直和非致死击飞固定复用 `TowardViewer Idle`，不额外增加基本敌人的动作资源。
- 存活纸片使用 `/Game/_Game/Material/Enemy/M_GobulinEnemySpriteMasked`，死亡切换 `/Game/_Game/Material/Enemy/M_GobulinEnemySpriteTranslucent`。前者降低普通敌潮的透明过绘，后者只在尸体阶段承担平滑淡出。
- 死亡 Translucent 父材质启用 `Cast Dynamic Shadow As Masked`，因此尸体是否投射动态阴影继续只服从 Archetype 的 `bCastShadow`：开启时存活与尸体阶段都投影，关闭时两个阶段都不投影。普通 MIC 应继承该父材质设置，不要在 Material Property Overrides 中将它关闭。
- 两个材质的可维护真源位于 `DShader/Material/Enemy/`，由 DreamShader 生成可读 Graph；不要在运行时叠加第二个 PaperFlipbookComponent。
- 九个槽都是有效基本敌人定义的必填项；固定资源路径只存在于编辑器资产初始化命令，运行时仍从 Archetype 的软引用读取。
- `bFaceLocalPlayer` 开启时，运行时纸片按 Paper2D 的局部轴约定水平朝向本地玩家；烘焙的基础旋转仍会保留。

方向选择完全属于本地表现层，不写入 `EEnemyState`，也不通过敌人事件或后续网络复制。未来不同客户端可以根据各自相机为同一个敌人选择不同的方向动画。

Paper2D 是当前内容制作源和 Actor 原型表现，不代表未来每个 Mass Entity 都持有一个 `UPaperFlipbookComponent`。接入 Mass 时应把相同的语义槽、帧率和渲染数据转换为共享 Fragment/实例渲染数据，Archetype 与战斗协议边界保持不变。

### 材质实例调参

两个父材质都允许在内容浏览器中右键创建普通 Material Instance。建议分别创建一个存活 MIC 和一个死亡 MIC，再将它们设置到 Archetype 的 `MaterialOverride` 与 `DeathMaterialOverride`；也可以先设置到 `GobulinEnemyPreviewActor.Presentation`，选择对应预览动作后烘焙回敌人资产。

`敌人纸片|材质实例` 分组暴露以下参数：

- `HitFlashColor` / `HitFlashPeakOpacity`：普通受击闪色及最亮时刻覆盖强度。
- `LethalFlashColor` / `LethalFlashPeakOpacity`：致死闪色及峰值覆盖强度。
- `DeathDarkenColor`：死亡逐黑最终趋近颜色。
- `SpriteBrightness`：纸片最终亮度倍率。
- `OpacityMultiplier`：仅死亡 Translucent 父材质拥有，用于调整尸体整体不透明度；运行时淡出仍会继续相乘。

材质实例负责同一敌人类型的共享美术参数，运行时 CPD 负责每只敌人的闪色时间、致死选择、逐黑和淡出进度，因此不会产生每敌人 MID。调参后仍需在 PIE 中观察受击峰值、死亡颜色和透明排序。

## EnemyPreviewActor 烘焙工作流

`AGobulinEnemyActor` 仍由子系统生成并标记为不可直接摆放。编辑器装配改用 `AGobulinEnemyPreviewActor`：

1. 重启编辑器后，在 **Place Actors / All Classes** 搜索 `GobulinEnemyPreviewActor`，直接放到测试关卡。
2. 选择该实例，把 `Target Archetype` 指向 `/Game/_Game/Enemy/EA_BasicEnemy`。
3. 点击 **从敌人资产加载**。胶囊尺寸、脚底锚点、Flipbook 和表现参数会同步到预览实例。
4. 在组件树选择 `CollisionCapsule` 调整半径/半高；选择 `Presentation` 调整 Flipbook、相对 Transform、颜色、材质、半透明排序和阴影。
5. 保持 PreviewActor 自身世界缩放为 `1,1,1`。需要缩放纸片时只改 `Presentation` 组件缩放。
6. 通过 `Preview Animation` 选择 `Idle`、`Run` 或 `Death`；预览 Idle/Run 时再用 `Preview Direction` 选择四个方向之一。编辑器视口未播放动画时开启视口 **Realtime**。
7. 点击 **烘焙到敌人资产**，然后在内容浏览器保存 `EA_BasicEnemy`。
8. 进入 PIE。SpawnArea 生成的 `AGobulinEnemyActor` 会读取刚烘焙的数据；无需在蓝图调用 `Get World Subsystem`。

每次烘焙只覆盖白名单数据：

- 胶囊半径与半高；
- `Presentation` 相对 `FeetAnchor` 的 Transform；
- 当前 `Preview Animation / Preview Direction` 对应的一个 Flipbook 槽；
- 当前 Idle/Run 槽的存活材质，或 Death 槽的死亡材质；另含 Sprite Color、Translucency Sort Priority、Cast Shadow；
- `bFaceLocalPlayer`。

不会烘焙 PreviewActor 的世界位置/旋转/缩放、关卡引用、临时动态材质，也不会自动保存资产到磁盘。`EA_BasicEnemy` 可正常 Undo，成功后会被标记为待保存。重新点击 **从敌人资产加载** 会覆盖预览实例中尚未烘焙的调整。

## 当前场景生成入口

当前使用 `AGobulinEnemySpawnArea` 将敌人接入关卡。它是可创建蓝图子类、可直接摆放的无 Tick Actor，内部使用一个 `UBoxComponent` 描述生成区域。

生成区域不会创建子 SpawnPoint Actor，也不会持有生成后的敌人 Actor。它只保存本地候选 Transform，运行时将这些地面锚点转换为 `FEnemySpawnRequest`，最终仍由 `UGobulinEnemySubsystem` 管理敌人。

### 职责划分

- SpawnArea：决定“区域中哪些地面位置可以生成”。
- 后续 Encounter/WaveController：决定“生成什么、多少、什么时候生成”。
- EnemySubsystem：加载定义、创建 Actor/Mass 后端、分配句柄、推进状态和回收。

第一版 SpawnArea 同时提供 `bSpawnOnBeginPlay` 和默认敌人配置，便于 PIE 与早期关卡直接使用；后续波次控制器可以关闭自动生成并调用其 `SpawnEnemies`。

### 地面候选生成规则

候选生成与运行时选择遵循以下规则：

1. 在 Box 的本地 XY 范围内按随机种子采样。
2. 从 Box 顶部向底部查询 `WorldStatic` 地面；可选择允许 `WorldDynamic`。
3. 拒绝超过 `MaximumGroundSlope` 的坡面。
4. 开启 `bRequireNavigation` 时，必须成功投射到 NavMesh。
5. 使用敌人 Archetype 的胶囊尺寸检查生成空间。
6. 使用 `MinimumSpacing` 检查同一批次的水平间距；有效间距不会小于胶囊直径。
7. 缓存不足或缓存点运行时失效时，在本批次中继续动态补充采样。

每个区域应只覆盖一个楼层。多层建筑应在每层分别放置区域，避免一次从上向下查询时把楼上和楼下混为同一个生成空间。

### 候选缓存

在关卡中选择 SpawnArea 实例后，可以使用以下编辑器按钮：

- `Rebuild Spawn Candidates`：扫描区域并把候选点以 SpawnBounds 本地 Transform 保存到地图。
- `Preview Spawn Candidates`：在视口中用绿色球体显示缓存点十秒。
- `Clear Spawn Candidates`：清空缓存；PIE 时改用完全运行时采样。

缓存点不是 Actor。移动区域后缓存会跟随区域 Transform，但地形或区域尺寸改变后仍应主动重建。PIE 提交前会再次查询地面、导航和占位，因此缓存不会绕过运行时安全检查。

### 批量提交和事件

- `UGobulinEnemySubsystem::SpawnEnemies` 保留请求顺序并返回对应命令 ID。当前 Actor 后端逐个执行，未来 Mass 后端可以在内部改为实体批创建。
- 每个敌人拥有独立 `FCombatCommandId`。
- 同一批次共享 `SpawnGroupId`；区域未指定固定组 ID 时，由 EnemySubsystem 自动分配。
- `OnSpawnBatchSubmitted`：同步返回请求数、提交数、拒绝数、组 ID 和命令 ID。
- `OnEnemySpawnResolved`：仅转发该区域拥有的异步成功或失败结果，蓝图不需要直接访问事件子系统。

EnemyArchetype DataAsset 自身是轻量硬引用，因此 SpawnArea 可以直接读取准确胶囊尺寸；Archetype 内的纸片和材质仍是软引用，并由 Asset Manager 的 `Presentation` Bundle 异步加载。

## 地面锚点语义

`FEnemySpawnRequest::SpawnTransform` 统一表示敌人脚底接触地面的逻辑锚点，不表示 Actor 胶囊体中心。Actor 后端会在创建时按 Archetype 胶囊半高向上偏移，并在 `FEnemySpawnedEvent` 中继续返回实际采用的地面锚点。

生成位置被墙体、其他 Pawn 或敌人占用时，EnemySubsystem 会返回 `SpawnBlocked`，不会把多个敌人强行堆叠或静默挪到未知位置。

## PIE 接入步骤

1. 在内容浏览器中以 `GobulinEnemySpawnArea` 为父类创建蓝图，例如 `BP_EnemySpawnArea`。
2. 把蓝图实例拖入关卡。
3. 在 `Enemy Archetype` 选择 `/Game/_Game/Enemy/EA_BasicEnemy`。
4. 设置 `Spawn Count`、`Minimum Spacing`、队伍、等级和强度。
5. 调整 `SpawnBounds` 的 Box Extent 或组件缩放，确保目标地面位于 Box 顶面与底面之间。
6. 在关卡实例 Details 中点击 `Rebuild Spawn Candidates`，确认出现足够的绿色候选点。
7. 保持 `Spawn On Begin Play` 开启并进入 PIE；区域会自动提交一个批次。

当前移动依赖 NavMesh。新建 SpawnArea 的 `Require Navigation` 默认开启，但上一轮已经保存到地图或蓝图中的实例可能仍保留旧值 `false`。请执行以下检查：

1. 在关卡中放置 `NavMeshBoundsVolume`，同时覆盖玩家活动区和敌人生成区。
2. 按 `P` 确认两处地面都有绿色导航覆盖。
3. 在现有 SpawnArea 实例上手动开启 `Require Navigation`。
4. 点击 `Rebuild Spawn Candidates`；旧候选缓存不会因为 C++ 默认值变化自动重建。

默认 `EA_BasicEnemy` 已使用 FieldPaladin 的四方向 Idle/Run，因此在 PIE 中可直接观察前、后、屏幕左、屏幕右以及移动/静止切换。死亡暂时使用 BattlePaladin 素材，视觉不一致属于已知占位状态。

受击与死亡 PIE 验收：每次剑击应先出现短促白闪、轻微后退/抬起并暂停追踪；飞行和硬直期间应保持面向玩家的 Idle，不随击飞速度切到侧向或背向。默认 `20 / 100` 伤害不应触发硬直。把单次伤害调到 `30` 以上或使用 `Combat.Attack.Melee.Heavy` 时，应进入更长硬直但不能被连续永久锁住。致死一击应闪红、立刻循环播放 Death Flipbook 并明显击飞；飞行中逐渐变黑，落地停留后平滑淡出。尸体应稳定落在 `WorldStatic / WorldDynamic` 地面或场景物体上，穿过玩家和存活敌人、不再被剑命中，同时能与其他尸体互相阻挡。EA 开启 `bCastShadow` 时，存活敌人和尸体都应投射动态阴影；关闭后两个阶段都不应投影。

接触伤害 PIE 验收：让一个敌人贴到玩家胶囊，首次接触应立即扣血，左下角生命值同步下降并出现短促红闪；持续接触约每 `0.8 s` 再扣一次，离开约 `15 cm` 表面间距后停止。快速离开再贴回不应立刻绕过上一伤害的冷却。隔墙靠近、敌人死亡或玩家死亡后都不应继续造成接触伤害。玩家生命归零后应显示死亡遮罩并可重开当前关卡。多个敌人接触时当前会分别结算。

怪潮堆积 PIE 验收：先完全关闭编辑器并重新打开项目，使新增移动组件和碰撞通道生效。在目标与 SpawnArea 之间放一段普通 `WorldStatic` 矮墙或门顶，确保墙前有 NavMesh、墙顶或墙后目标仍在搜索范围内；一次生成至少约 `12-20` 个敌人并适当降低 SpawnArea 间距。单只或少量敌人应被挡住，局部聚集达到阈值后，后排应出现连续抬升、互相遮叠并有敌人越过顶部，不能整齐吸附为固定上下站位。越过障碍且重新获得路径的敌人应从 `CrowdPushing` 恢复 `Moving`；玩家跳回底层后，原先充当梯子的敌人也应在一次重试间隔后重新追踪。敌人越过无硬边界的平台边缘时应保持原推进方向并立即进入 Falling，不得先沿边向中心滑动，也不得出现胶囊下半球持续悬挂。高悬崖现在同样允许自然跌落；不允许进入或跌落的位置必须放置覆盖完整高度的空气墙或 `GobulinEnemySwarmBoundary`，并由关卡 KillZ/回收边界处理漏网单位。

若希望由门、触发盒或关卡蓝图控制生成：

1. 关闭 `Spawn On Begin Play`。
2. 保存 SpawnArea 实例引用。
3. 调用 `Spawn Default Batch`，或传入数量调用 `Spawn Enemies`。
4. 按需绑定 `On Spawn Batch Submitted` 与 `On Enemy Spawn Resolved`。

`AGobulinEnemyActor` 标记为 `NotPlaceable`，不要直接拖入关卡。它应始终由敌人子系统创建。

## 怪潮移动调试链路

调试信息由 EnemySubsystem 集中采样和绘制，不给每个敌人挂 `WidgetComponent`，避免大量屏幕空间控件遮挡怪潮并引入额外 Tick、布局和渲染开销。根据这条链路确认的第一批根因已经修复：地面水平冲量被制动清零、`CrowdPushing` 永久提前返回，以及边缘策略只有“全禁/全开”两种选择。

### 全场可视化

在 PIE 控制台输入：

- `gobulin.Enemy.Debug 0`：关闭调试绘制。
- `gobulin.Enemy.Debug 1`：显示所有敌人的战斗胶囊、怪潮粒子体、实际速度和目标连线；只给停滞敌人及手动选中敌人显示文字。
- `gobulin.Enemy.Debug 2`：在模式 1 基础上显示所有敌人的头顶文字。
- `gobulin.Enemy.DebugHandle <Index>`：选择一个句柄索引，额外显示其邻居查询范围、当前移动意图、导航路径和怪潮三类作用量。头顶句柄格式为 `Index:Generation`，命令只填写冒号前的 `Index`。
- `gobulin.Enemy.DebugMaxLabels 64`：限制同屏文字数量；不会限制碰撞体和向量绘制。
- `gobulin.Enemy.DebugDump 1`：把当前所有敌人的一次性快照写入 Output Log，然后自动复位为 `0`。可搜索 `[EnemyDebug]`。

颜色约定：

- 青色/橙色/红色战斗胶囊：普通、`CrowdPushing`、已检测到目标进展停滞。
- 黄色球体：怪潮求解使用的虚拟粒子体；它不是物理碰撞体，也不可能真正卡在 Mesh 边缘。若看起来是黄色球体贴住墙沿，实际发生接触的是外层青色/橙色 Character 根胶囊。
- 绿色细线：当前敌人到目标最后已知位置。
- 青色箭头：CharacterMovement 的实际速度。
- 选中敌人周围的灰色球体：邻居查询范围。
- 选中敌人的绿色、橙色、品红箭头：本帧实际采用的目标驱动、水平分离、垂直抬升速度修正。
- 选中敌人脚底的绿色/红色小球与连线：脚底中心支撑扫描的位置和半径；绿色为有效支撑，红色为已失去中心支撑。
- 白色点和折线：当前移动意图位置与 PathFollowing 正在持有的导航路径。

头顶信息中的关键字段：

- `State / Move`：敌人规则状态与移动协议状态，重点区分 `Moving / CrowdPushing / Reached / Blocked / Failed`。
- `PF`：PathFollowing 状态；尾部 `*` 表示 AIController 仍持有活动移动意图。
- `MM / G / Ledge / Support / R/D`：CharacterMovement 模式、是否落地、是否允许走下边缘、中心支撑状态，以及支撑半径/向下吸附距离。基础存活敌人的 `Ledge` 应保持 `1`。
- `Vxy / Vz`：实际水平和垂直速度。
- `N / P`：局部邻居数量与局部压力。
- `Retry`：`CrowdPushing` 距离下一次 NavMesh 只读路径探测的剩余秒数；各敌人应错峰变化，显示 `-` 表示当前不在等待探测。
- `dMove`：最近约 `0.5 s` 的实际水平位移。
- `dGoal`：同一采样窗内与目标三维距离的缩短量；正数表示靠近，负数表示远离。
- `NoProg`：仍有目标且未处于有效接触时，连续没有取得最小目标进展的时间。
- `NavReject`：`1` 表示当前 NavMesh 候选路径已经被 Character 的实际执行结果否决，不能靠定时重试直接恢复。
- `Rec Z/T/G`：相对拒绝时刻的敌人中心高度变化、目标移动距离、敌人到目标距离改善量；默认任一项分别达到 `45 / 75 / 75 cm` 后才有资格重新探测路径。
- `Evt`：最后一次调试事件，如路径完成、移动状态变化、清除目标、进入/离开接触和停滞/恢复。

`TargetProgressStalled` 是观测标记，不是新的玩法状态：当前条件为仍有目标、未接触、约 `1.5 s` 未取得至少 `5 cm` 的目标进展且水平速度低于 `10 cm/s`。连续堆积敌人的正式导航看门狗采用同一组 Archetype 参数；调试标记本身仍不能单独作为根因结论。

### 选中单体与时间线

- PIE 中按撇号键 `'` 打开 Gameplay Debugger，把准星对准异常敌人，查看 `GobulinEnemy` 分类。它会显示完整状态、PathFollowing、MovementMode、目标/接触、邻居压力、采样进展及三类怪潮修正，并在世界中绘制该敌人的路径和作用量。
- 输入 `vislog record` 开始 Visual Logger 记录，复现问题后输入 `vislog stop`；输入 `vislog` 可打开 Visual Logger 窗口。敌人的状态转换、移动状态转换、目标获得/清除、接触进入/离开以及进展停滞/恢复都会写入时间线。

### 本问题的回归验收顺序

1. 保持原来的半身高 Mesh、上下两层 NavMesh、玩家站在上层和同一批敌人数量，不先改任何怪潮参数。
2. 输入 `gobulin.Enemy.Debug 1` 与 `vislog record`，从敌人开始聚集前进行记录。
3. 选中一个从 Mesh 正面中心接近边缘的敌人。接近过程中 `Ledge` 应始终为 `1`；脚底小球由绿色 `Support:Valid` 变为红色 `Support:Invalid` 时，`MM` 应在同一次移动更新中进入 `Falling`，不能等待 `0.2 s` 或 `1.5 s`。
4. 再观察从左右两侧斜向接近边缘的敌人。它们必须保持原来的目标推进分量直接越边，不能沿边缘向中心滑动；胶囊中心越过边缘后不能由下半球外沿继续支撑。
5. 在平地三角形接缝、小台阶和斜坡上行走，确认 `Support` 不会无故变红或造成连续 Walking/Falling 抖动。若有接缝误判，先小幅增大 `GroundSupportRadius`；若仍能看到悬边，减小该值。普通调参范围为 `2-4 cm`。
6. 在真正不可跌落的位置放置 `EnemySwarmBoundary` 或空气墙，确认敌人无法越过；未放边界的高悬崖允许自然跌落，这属于当前正式规则而不是探测失败。
7. 让怪潮把已否决路径的敌人抬到新的高度，或明显移动玩家，确认对应 `Rec` 值越过阈值后才发生只读路径探测；路径成立时 `Move` 才能从 `CrowdPushing` 回到 `Moving`。所有进入 Falling 的敌人在空中不得发生导航重试造成的水平速度归零，落地后必须继续寻路。
8. 输入一次 `gobulin.Enemy.DebugDump 1`，确认 Output Log 只产生一批 `[EnemyDebug]` 快照且命令自动复位；日志应包含 `supportSample / centerSupport / supportRadius / snapDown / navRejected`。随后输入 `vislog stop`；若仍有异常，截图应同时包含脚底支撑球、敌人头顶标签、战斗胶囊和黄色怪潮体。

## 后续开发顺序

1. 在 PIE 中人工验收普通击退、阈值硬直、致死击飞、尸体互撞与材质时间参数。

3. PIE 调整连续堆积的粒子半径、密度阈值、向上压力与矮墙高度，确定基本敌人的正式默认值。
