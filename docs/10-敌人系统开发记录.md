# 敌人系统开发记录

> 最后更新：2026-08-19  
> 状态：最小敌人地基、场景生成、Paper2D 四方向 Idle/Run 表现、索敌与 NavMesh 移动闭环已落地

## 文档用途

本文档持续记录敌人系统的协议、运行时实现、关卡接入方式、PIE 验收方法和后续演进方向。

代码与已保存的资产是事实来源；本文档用于解释当前边界和记录后续决策。

## 当前设计边界

敌人上层逻辑只依赖句柄、请求、状态和事件，不直接依赖 Actor。当前以 Actor 作为最小运行时后端，后续可增加 Mass Entity 后端而不修改战斗协议。

- `FCombatantHandle`：跨系统引用敌人的稳定句柄。
- `FCombatDamageRequest` / `FCombatDamageResult`：伤害输入和结果协议。
- `FEnemySpawnRequest` / `FEnemySpawnResultData`：单个敌人的生成命令和异步结果。
- `FCombatantSnapshot`：目标查询使用的后端中立队伍、位置与存活快照。
- `FEnemyTargetData` / `FEnemyMoveIntent` / `FEnemyMovementData`：不含 Actor、Controller 或路径对象的目标和移动协议。
- `EEnemyState`：敌人生命周期状态。
- `UCombatEventSubsystem`：C++ 事件总线。
- `UGobulinEnemySubsystem`：World 级敌人生命周期服务，负责定义加载、实例创建、状态推进和回收。
- `AGobulinEnemyActor`：基于 `ACharacter` 的当前 Actor 后端，承载碰撞、地面移动和表现，不作为关卡直接摆放对象。
- `AGobulinEnemyAIController`：只执行 NavMesh 路径请求，不拥有索敌、状态机或攻击决策。
- `UGobulinEnemyPresentationComponent`：基于原生 `UPaperFlipbookComponent` 的 Actor 表现适配器。
- `AGobulinEnemySpawnArea`：可放入关卡的区域生成入口，负责寻找地面锚点并提交批量请求。
- `UGobulinEnemyArchetype`：Actor 与未来 Mass 后端共用的数据定义。
- `AGobulinEnemyPreviewActor`：仅编辑器存在的装配台，用于在关卡视口调整身体与纸片表现并烘焙回 Archetype。

当前最小状态流为：

`Inactive -> Spawning -> SeekingTarget -> Moving <-> ReadyToAttack -> Dying -> Inactive`

目标失效或超出保持距离时，`Moving / ReadyToAttack` 会返回 `SeekingTarget`。`AttackWindup / AttackActive / AttackRecovery` 已保留在协议中，但本轮尚未执行攻击和伤害。

## 默认敌人定义

- 资产：`/Game/_Game/Enemy/EA_BasicEnemy`
- Primary Asset ID：`EnemyArchetype:EA_BasicEnemy`
- 资源扫描目录：`/Game/_Game/Enemy`
- 身体：胶囊半径 `34 cm`、半高 `88 cm`
- 默认移动表现：`FieldPaladin__Idle_D/U/L/R` 与 `FieldPaladin__Run_D/U/L/R`
- 当前临时死亡表现：`BattleMage__Downed`（FieldPaladin 尚未提供死亡 Flipbook）
- 移动速度：`300 cm/s`
- 搜索/丢失目标距离：`5000 / 6500 cm`
- 进入攻击准备/恢复追踪距离：`160 / 220 cm`
- 行为决策间隔：`0.25 s`；导航失败重试：`1.0 s`
- Actor 基础避让：RVO 开启，查询半径 `250 cm`

## 索敌与移动

索敌和移动决策归 `UGobulinEnemySubsystem`，而不是 AIController、Behavior Tree 或每个敌人的 Actor Tick。

### 战斗单位快照

`UCombatantRegistrySubsystem` 除了维护句柄到 Actor 后端的映射，还提供 `FCombatantSnapshot`：

- `Handle`：稳定战斗句柄；
- `TeamId`：用于排除同队目标；
- `Location`：本次决策读取的位置快照；
- `bActive`：死亡或不可再成为目标时为 false。

玩家默认注册为队伍 `1`，SpawnArea 默认生成队伍 `0`。敌人只在搜索半径内选择最近的存活异队单位；距离完全相同时按句柄排序，保证结果稳定。当前不检查视野锥和视线遮挡。

### 决策与路径执行

- EnemySubsystem 按 Archetype 的 `DecisionInterval` 分批更新敌人，并按句柄错开更新时间。
- `FEnemyMoveIntent` 只包含目标句柄、目的地快照、速度、停止距离、时间和递增序号。
- Actor 后端把意图交给轻量 `AGobulinEnemyAIController`，由 NavMesh 和 `UCharacterMovementComponent` 跟随移动目标。
- Controller 不使用 Behavior Tree、Blackboard 或 AI Perception；路径完成后只把 `Reached / Blocked / Failed` 结果回报 EnemySubsystem。
- `ReadyToAttack` 使用 `AttackReadyDistance / ResumeMoveDistance` 两个阈值形成滞回，避免玩家在距离边缘移动时频繁启停移动表现。
- 路径失败会清理当前目标并等待 `NavigationRetryDelay`，避免没有 NavMesh 时每帧重复申请路径。
- 当前 Actor 后端启用 CharacterMovement RVO 作为基础避让；这不是未来 Mass 的拥挤解法。

### 事件边界

- `FEnemyTargetChangedEvent`：只在获得、失效、超距或导航失败导致目标变化时发布。
- `FEnemyMoveStatusChangedEvent`：只发布 `Moving / Reached / Blocked / Failed` 等语义变化。
- 目标位置和路径跟随的逐帧更新不进入事件总线。

未来 Mass 后端应将 `FCombatantSnapshot` 接到空间查询，把 RuntimeStats 放入 Const Shared Fragment，把 Target/Movement 放入每实体 Fragment；不为普通杂兵创建 ACharacter 或 AIController。

## 战斗命中通道

近战形状查询统一使用项目专用 Trace Channel：`CombatTrace`（C++ 为 `ECC_GameTraceChannel2`），不再复用 `Visibility`。

- 默认响应为 `Block`，因此场景遮挡仍能截断一次武器查询。
- 敌人胶囊对 `CombatTrace` 显式设为 `Overlap`，`SweepMultiByChannel` 可以在命中多个敌人后继续查询。
- 敌人胶囊保持 `Pawn` Object Type，移动、占位和生成空间检查仍沿用 Pawn 语义。
- 查询命中依赖 Collision Response，不依赖 `Generate Overlap Events`；敌人无需开启逐帧重叠事件。
- 修改通道配置或首次启用 Paper2D 后必须重启编辑器，已有 PIE 会话不会热重载碰撞通道定义。

## Paper2D 表现层

当前 Actor 后端不再读取自研图集行列并由程序切帧，而是直接消费虚幻原生 `UPaperFlipbook`。Flipbook 的帧、帧率、关键帧 Sprite 和默认材质均可在 Paper2D 编辑器中调整。

运行时组件层级固定为：

`CollisionCapsule -> FeetAnchor -> Presentation (PaperFlipbook)`

- Actor 世界原点仍是胶囊中心。
- `FeetAnchor` 始终位于胶囊底部。
- `VisualTransformFromGround` 保存纸片相对脚底的位移、旋转和缩放，胶囊尺寸变化不会破坏脚底对齐。
- 基本敌人包含四方向 `Idle`、四方向 `Run` 与一个 `Death`，合计九个表现槽。
- 每套方向槽分别表示朝向观察者、远离观察者、向观察者屏幕左侧和右侧移动；不是世界东南西北，也不读取目标方向。
- FieldPaladin 资源映射为：`D -> TowardViewer`、`U -> AwayFromViewer`、`L -> ViewerLeft`、`R -> ViewerRight`。
- 运行时使用敌人的实际水平速度相对本地相机选方向，因此 NavMesh 转弯和 RVO 避让也能得到正确表现。
- 速度达到 `MinimumDirectionalSpeed` 时循环播放该方向 `Run`；低于阈值时循环播放上一次有效方向的 `Idle`。
- `DirectionSwitchHysteresis` 在四方向分界附近提供切换滞后；同一动作内切换方向时继承标准化播放进度，`Idle <-> Run` 切换则从头播放。
- `Death` 单次播放。出生、索敌、攻击协议预留状态和受击状态目前复用当前移动表现，不额外增加基本敌人的动作资源。
- 九个槽都是有效基本敌人定义的必填项；固定资源路径只存在于编辑器资产初始化命令，运行时仍从 Archetype 的软引用读取。
- `bFaceLocalPlayer` 开启时，运行时纸片按 Paper2D 的局部轴约定水平朝向本地玩家；烘焙的基础旋转仍会保留。

方向选择完全属于本地表现层，不写入 `EEnemyState`，也不通过敌人事件或后续网络复制。未来不同客户端可以根据各自相机为同一个敌人选择不同的方向动画。

Paper2D 是当前内容制作源和 Actor 原型表现，不代表未来每个 Mass Entity 都持有一个 `UPaperFlipbookComponent`。接入 Mass 时应把相同的语义槽、帧率和渲染数据转换为共享 Fragment/实例渲染数据，Archetype 与战斗协议边界保持不变。

## EnemyPreviewActor 烘焙工作流

`AGobulinEnemyActor` 仍由子系统生成并标记为不可直接摆放。编辑器装配改用 `AGobulinEnemyPreviewActor`：

1. 重启编辑器后，在 **Place Actors / All Classes** 搜索 `GobulinEnemyPreviewActor`，直接放到测试关卡。
2. 选择该实例，把 `Target Archetype` 指向 `/Game/_Game/Enemy/EA_BasicEnemy`。
3. 点击 **从敌人资产加载**。胶囊尺寸、脚底锚点、Flipbook 和表现参数会同步到预览实例。
4. 在组件树选择 `CollisionCapsule` 调整半径/半高；选择 `Presentation` 调整 Flipbook、相对 Transform、颜色、材质、半透明排序和阴影。
5. 保持 PreviewActor 自身世界缩放为 `1,1,1`。需要缩放纸片时只改 `Presentation` 组件缩放。
6. 通过 `Preview Animation` 选择 `Idle`、`Run` 或 `Death`；预览 Idle/Run 时再用 `Preview Direction` 选择四个方向之一。编辑器视口未播放动画时开启视口 **Realtime**。
7. 点击 **烘焙到敌人资产**，然后在内容浏览器保存 `EA_BasicEnemy`。
8. 进入 PIE。SpawnArea 生成的 `AGobulinEnemyActor` 会读取刚烘焙的数据；无需在蓝图调用 `Get World Subsystem`。

每次烘焙只覆盖白名单数据：

- 胶囊半径与半高；
- `Presentation` 相对 `FeetAnchor` 的 Transform；
- 当前 `Preview Animation / Preview Direction` 对应的一个 Flipbook 槽；
- 显式材质覆盖、Sprite Color、Translucency Sort Priority、Cast Shadow；
- `bFaceLocalPlayer`。

不会烘焙 PreviewActor 的世界位置/旋转/缩放、关卡引用、临时动态材质，也不会自动保存资产到磁盘。`EA_BasicEnemy` 可正常 Undo，成功后会被标记为待保存。重新点击 **从敌人资产加载** 会覆盖预览实例中尚未烘焙的调整。

## 当前场景生成入口

当前使用 `AGobulinEnemySpawnArea` 将敌人接入关卡。它是可创建蓝图子类、可直接摆放的无 Tick Actor，内部使用一个 `UBoxComponent` 描述生成区域。

生成区域不会创建子 SpawnPoint Actor，也不会持有生成后的敌人 Actor。它只保存本地候选 Transform，运行时将这些地面锚点转换为 `FEnemySpawnRequest`，最终仍由 `UGobulinEnemySubsystem` 管理敌人。

### 职责划分

- SpawnArea：决定“区域中哪些地面位置可以生成”。
- 后续 Encounter/WaveController：决定“生成什么、多少、什么时候生成”。
- EnemySubsystem：加载定义、创建 Actor/Mass 后端、分配句柄、推进状态和回收。

第一版 SpawnArea 同时提供 `bSpawnOnBeginPlay` 和默认敌人配置，便于 PIE 与早期关卡直接使用；后续波次控制器可以关闭自动生成并调用其 `SpawnEnemies`。

### 地面候选生成规则

候选生成与运行时选择遵循以下规则：

1. 在 Box 的本地 XY 范围内按随机种子采样。
2. 从 Box 顶部向底部查询 `WorldStatic` 地面；可选择允许 `WorldDynamic`。
3. 拒绝超过 `MaximumGroundSlope` 的坡面。
4. 开启 `bRequireNavigation` 时，必须成功投射到 NavMesh。
5. 使用敌人 Archetype 的胶囊尺寸检查生成空间。
6. 使用 `MinimumSpacing` 检查同一批次的水平间距；有效间距不会小于胶囊直径。
7. 缓存不足或缓存点运行时失效时，在本批次中继续动态补充采样。

每个区域应只覆盖一个楼层。多层建筑应在每层分别放置区域，避免一次从上向下查询时把楼上和楼下混为同一个生成空间。

### 候选缓存

在关卡中选择 SpawnArea 实例后，可以使用以下编辑器按钮：

- `Rebuild Spawn Candidates`：扫描区域并把候选点以 SpawnBounds 本地 Transform 保存到地图。
- `Preview Spawn Candidates`：在视口中用绿色球体显示缓存点十秒。
- `Clear Spawn Candidates`：清空缓存；PIE 时改用完全运行时采样。

缓存点不是 Actor。移动区域后缓存会跟随区域 Transform，但地形或区域尺寸改变后仍应主动重建。PIE 提交前会再次查询地面、导航和占位，因此缓存不会绕过运行时安全检查。

### 批量提交和事件

- `UGobulinEnemySubsystem::SpawnEnemies` 保留请求顺序并返回对应命令 ID。当前 Actor 后端逐个执行，未来 Mass 后端可以在内部改为实体批创建。
- 每个敌人拥有独立 `FCombatCommandId`。
- 同一批次共享 `SpawnGroupId`；区域未指定固定组 ID 时，由 EnemySubsystem 自动分配。
- `OnSpawnBatchSubmitted`：同步返回请求数、提交数、拒绝数、组 ID 和命令 ID。
- `OnEnemySpawnResolved`：仅转发该区域拥有的异步成功或失败结果，蓝图不需要直接访问事件子系统。

EnemyArchetype DataAsset 自身是轻量硬引用，因此 SpawnArea 可以直接读取准确胶囊尺寸；Archetype 内的纸片和材质仍是软引用，并由 Asset Manager 的 `Presentation` Bundle 异步加载。

## 地面锚点语义

`FEnemySpawnRequest::SpawnTransform` 统一表示敌人脚底接触地面的逻辑锚点，不表示 Actor 胶囊体中心。Actor 后端会在创建时按 Archetype 胶囊半高向上偏移，并在 `FEnemySpawnedEvent` 中继续返回实际采用的地面锚点。

生成位置被墙体、其他 Pawn 或敌人占用时，EnemySubsystem 会返回 `SpawnBlocked`，不会把多个敌人强行堆叠或静默挪到未知位置。

## PIE 接入步骤

1. 在内容浏览器中以 `GobulinEnemySpawnArea` 为父类创建蓝图，例如 `BP_EnemySpawnArea`。
2. 把蓝图实例拖入关卡。
3. 在 `Enemy Archetype` 选择 `/Game/_Game/Enemy/EA_BasicEnemy`。
4. 设置 `Spawn Count`、`Minimum Spacing`、队伍、等级和强度。
5. 调整 `SpawnBounds` 的 Box Extent 或组件缩放，确保目标地面位于 Box 顶面与底面之间。
6. 在关卡实例 Details 中点击 `Rebuild Spawn Candidates`，确认出现足够的绿色候选点。
7. 保持 `Spawn On Begin Play` 开启并进入 PIE；区域会自动提交一个批次。

当前移动依赖 NavMesh。新建 SpawnArea 的 `Require Navigation` 默认开启，但上一轮已经保存到地图或蓝图中的实例可能仍保留旧值 `false`。请执行以下检查：

1. 在关卡中放置 `NavMeshBoundsVolume`，同时覆盖玩家活动区和敌人生成区。
2. 按 `P` 确认两处地面都有绿色导航覆盖。
3. 在现有 SpawnArea 实例上手动开启 `Require Navigation`。
4. 点击 `Rebuild Spawn Candidates`；旧候选缓存不会因为 C++ 默认值变化自动重建。

默认 `EA_BasicEnemy` 已使用 FieldPaladin 的四方向 Idle/Run，因此在 PIE 中可直接观察前、后、屏幕左、屏幕右以及移动/静止切换。死亡暂时使用 BattleMage 素材，视觉不一致属于已知占位状态。

若希望由门、触发盒或关卡蓝图控制生成：

1. 关闭 `Spawn On Begin Play`。
2. 保存 SpawnArea 实例引用。
3. 调用 `Spawn Default Batch`，或传入数量调用 `Spawn Enemies`。
4. 按需绑定 `On Spawn Batch Submitted` 与 `On Enemy Spawn Resolved`。

`AGobulinEnemyActor` 标记为 `NotPlaceable`，不要直接拖入关卡。它应始终由敌人子系统创建。

## 后续开发顺序

1. 在 PIE 中人工验收朝向/远离/屏幕左/屏幕右四方向、路径转弯、分界滞后以及 Run/Idle 切换。
2. 重新确定基本敌人的近战攻击方式后，再实现攻击阶段与玩家受伤闭环；不采用单纯接近玩家立即扣血。
3. 增加受击打断、攻击冷却和攻击名额调度。
4. 增加 Encounter/WaveController，由它组合多个 SpawnArea。
5. 增加视野外、距离环和区域容量等敌潮导演规则。
6. 在敌人数量和行为稳定后接入 Mass 后端与表现数据转换。
